# 道路核查与资源调度（2026-08-28 增量）

状态：源代码和业务单元测试可用；实际 MapGIS 网络及桌面操作尚未验收。

## 桌面入口

识别 → 空间化并加载 MapGIS → 建筑／道路核查 → 道路核查与资源调度。
先导入真实调度任务 JSON，再选择目的节点、资源类型、需求数，执行原生计算。
结果表显示每项资源分配容量、预计分钟、公里数和路径网络边；导出按钮保存 HTML 与 JSON 证据。
所有操作只生成建议，不修改源路网、不扣减资源、不发送实际指令。

## 必需数据

当前二维地图需要建筑面、道路线和 NetCls 网络图层。道路必须是该网络的源要素类，不能仅因数字 ID 一致便认为匹配。
通过 SDK `getSubEdgeS(源类ID, 要素ID)` 找到所有子边，登记 CLOSED 时全部设为本次分析障碍。
网络必须使用投影坐标；经纬度网络不直接计算公里数。分钟权字段必须已由 MapGIS 正确创建和赋值。
最终边权有效性、方向、路径和长度须在真实业务数据上验收。

JSON 字段：

- `networkUrl`：当前地图打开的 NetCls 实际 URL。
- `forwardMinutes`、`reverseMinutes`、`nodeMinutes`：已注册的分钟阻抗权名称。
- `kilometersPerNetworkUnit`：网络长度单位到公里的转换，例如米为 0.001；不能按猜测填写。
- `nodes`：业务节点名称到原生节点 ID 的对象映射。
- `resources`：对象数组，每项包含 `id`、`type`、`node`、`capacity`。资源类型和容量单位须与需求一致。
- `type`、`destination`、`demand`：资源类型、目标节点名称、正整数需求。
- `reviews`：对象数组，包含 `dataset`（核查道路数据源 URL）、`featureId`、`status`、`evidence`。
  status 仅支持 UNREVIEWED / PASSABLE / CLOSED；已核查项必须提供来源、时间和依据说明。

不要把文档中的字段名当示例数据提交；程序没有预置虚构资源或网络 ID。
未核查道路不会默认为通行：仍有 UNREVIEWED 时拒绝输出调度建议。
不在当前候选实体集合中的核查项、重复核查、缺失映射都会报错。
当前仅联动本次候选道路；全域既有交通管制、动态轻/重淹权重、资源时效与真实派单尚未实现，不得用于实战。

## 报告范围

报告覆盖数据来源、实体相交证据、核查道路、网络阻断边、分配建议、容量缺口和验收局限。
完整洪水范围、受淹面积、建筑损毁、人口、社区风险等级目前仍未知，不用 0 或像素数冒充。
这份业务报告不是完整灾情终验报告。

不改授权、不替换 MapGIS、不将进程存活视为通过。2026-08-28 当前普通会话实测 DLL 初始化失败，见 runtime/native-raster-20260828a 和 b。
官方授权桌面正常运行的事实不等于独立 JVM 可加载这些 DLL；需在官方运行环境内完成后续验收。
