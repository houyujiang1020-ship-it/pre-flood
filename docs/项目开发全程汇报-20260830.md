# 智洪卫（MapGIS-FloodGuard）项目开发全程汇报

统计期间：2026年8月23日至2026年8月30日。依据项目现存开发文档、运行日志、测试报告、训练记录和原生业务验收JSON整理。

## 一、汇报结论

项目已由空工程推进到“MapGIS原生桌面插件 + 双时相AI研究推理 + 地理参考结果加载 + 原生演练路网 + 资源与封路演练 + 可追溯报告”的开发验证系统。

目前不是完整参赛成品。最新验收门禁为 **4/9项通过**；这不是按工作量计算的44%完成率。模型精度、完整灾损分析、生产推理、真实资源台账和正式业务验收仍不合格或缺少证据。

本汇报不将代码编译、单元测试、演练数据或进程启动冒充实际业务验收。不将模型像素结果当作真实灾情。

## 二、开发目标与技术路线

- 目标：面向洪涝灾害，识别受淹建筑与道路，结合MapGIS空间核查、道路阻断和资源调度，提供可追溯的辅助决策结果。
- 桌面：MapGIS 10安装SDK、Java21插件、JavaFX交互；独立Java业务核心使用Java17。
- 服务：FastAPI异步推理、Java HTTP客户端、任务进度与结构化错误。
- 模型：SpaceNet8官方SiamUnet_diff研究架构，PyTorch/CUDA；研究预处理环境与最终AI服务隔离。
- 数据：官方SpaceNet8双时相影像及建筑/道路标注；资源数据分真实来源实体和明确虚构的演练台账。
- 原生GIS：地图加载、空间参考核验、栅格空间化、斑块/实体核查、HDF要素数据集和NetCls网络分析。

1. 排查资源吸附失败，不任意扩大25米阈值；建立独立endpoint-v2端点演练，保留原台账。
2. 发现SDK默认getEdgeLength固定返回1，不能作为真实米制边长；增加原生几何长度、mpLength和网络权的交叉核验。

4. 闪退日志确认NetAnalyseNative.jni_setNetAnalyOption访问异常；前置准备失败后仍调用原生路由是已知危险路径。增加严格门禁：权重/绑定/重开/读回失败即跳过路由，不继续调用JNI。
5. 处理封闭唯一通路后SDK以空PathInfo表示不可达的返回形态，仅在合法封路上下文中接受。
6. 形成原生资源绑定、非零基线路径、命中基线路径的封路及封路后重算证据。
7. 最新验收允许“已验证原生几何+原生最短距离+统一演练速度”的演练阻抗方式；不能据此声称任意实际交通规则或命名分钟权全部通过。

## 四、主要问题闭环

| 问题 | 原因或证据 | 处理及当前结论 |
| --- | --- | --- |
| 官方软件能打开，脚本却报授权失败 | 启动环境/产品上下文不一致，早期强制lic判断不适用 | 对齐官方宿主；已有后续原生成功证据，不绕过授权 |
| 识别按钮没反应或禁用 | 插件扫描命名规则、初始化前启用状态被缓存 | 修复入口与状态逻辑，后续面板实际打开 |
| 页面仍提示fallback | 文本硬编码或模型身份返回错误 | 查询实际后端与权重身份 |
| 地图空白/大面积红色 | 显示格式与模型误检是两类问题 | RGB显示/网格核验处理显示；模型误检仍未解决 |
| 建库/建类/建网失败 | 名称超长、重载错误、遗漏数据集、重用已关闭对象 | 逐项修复，现场原生拓扑已通过 |
| 资源吸附失败 | 内部顶点不一定是网络节点 | 端点演练通过，不宣称任意资源接入成功 |
| 距离异常 | 默认边长固定返回1 | 原生几何交叉验证，拒绝可疑长度 |
| 创建演练路网后闪退 | 前置失败仍调用原生分析 | 添加失败门禁；不保证第三方SDK永不崩溃 |
| Demo state already exists | 上次会话/状态未清理 | 身份核验与明确停止顺序，拒绝盲目杀进程 |
| 下载慢/续传风险 | 通道速度及分段布局/合并缺陷 | 支持受控并发，修复恢复与合并；用户数据已下载，不再重复下载 |
| Java class版本冲突 | Java17测试误用Java21产物 | 隔离构建和SDK专属测试，复测通过 |
| 模型精度低 | 真实评估确认误检/漏检；缩放、样本/区域泛化等仍需研究 | 两轮训练与校准完成，但未达标、未部署 |
