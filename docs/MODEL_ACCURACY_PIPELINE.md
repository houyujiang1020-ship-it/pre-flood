# AI accuracy research pipeline

The original E4 checkpoint and the Java/MapGIS/FastAPI output contract remain unchanged. This pipeline is an opt-in research path. Its four channels stay in the order non-flooded building, flooded building, non-flooded road, flooded road. Status fusion returns soft probabilities; there is no hard mutual-exclusion argmax.

## Entrypoints

Run `scripts/run_accuracy_pipeline.ps1 -Mode Audit -RunId <unique-id>` from PowerShell for split assertions and an independently reloaded fixed-0.5 E4 result. `-MineFullTrain` adds train-only flooded-road error mining and visual audit. To train a new four-class candidate, copy an existing candidate JSON, choose a new `model_id` and empty `output_dir`, and run `scripts/run_accuracy_pipeline.ps1 -Mode Train -Config <path> -RunId <unique-id>`. The script trains, evaluates, applies the development promotion rule, and produces a separate threshold diagnostic. It never overwrites prior run directories.

Relevant independent modules are `app/training/class_aware_crop.py`, `app/training/hard_negative_sampler.py`, `tools/mine_failure_cases.py`, `tools/rasterize_gis_labels.py`, `app/training/foundation_flood_models.py`, `app/training/train_flood_change.py`, `app/training/inference_fusion.py`, `pseudo_label/generate_pseudo_labels.py`, `pseudo_label/filter_pseudo_labels.py`, `app/training/mean_teacher.py`, and `app/training/train_teacher_student.py`. The two-stage and teacher-student branches are isolated experiments, not enabled in FastAPI.

The original labeled image folders are under `11/Germany_Training_Public` and `11/Louisiana-East_Training_Public`; their exact frozen membership and PRE/POST paths are in `experiments/accuracy-pipeline-20261005/data_split_manifest.csv`. New *unlabeled*, georeferenced PRE/POST pairs need an explicit JSON manifest with `split: "unlabeled_train"` and `items: [{"sample_id": "...", "pre_image": "...", "post_image": "..."}]`, where paths resolve from the repository root. Do not place validation or Louisiana-West test imagery in this manifest. Run `python -m pseudo_label.generate_pseudo_labels --manifest <manifest.json> --config config/pseudo_label.high_confidence-20261005.json --output <new-dir>`; inspect `pseudo_label_stats.json` before any use. The current synthetic example in `experiments/accuracy-pipeline-20261005/pseudo-smoke-input/` needs `--allow-synthetic-smoke` and cannot be promoted as training evidence.

For teacher-student research, create a new config based on `config/training.teacher-student-smoke-20261005.json`, replace the pseudo manifest with eligible real paired imagery, select a new `model_id`/`output_dir`, and run `python app/training/train_teacher_student.py --config <new-config>`. Its `--resume` option restores student/EMA/optimizer/scaler/RNG only when config, pseudo manifest, and initialization hashes match. The original `train_full.py --resume` likewise requires the run signature. Do not pass the synthetic smoke flag for a real experiment.

An opt-in probability export is `python scripts/export_extended_prediction.py --pre <pre.tif> --post <post.tif> --checkpoint <four-class.pth> --output <new-dir>`; it creates `extended_prediction.json` and `probability_maps.npz`. This is a separate research artifact, leaves `flood_prediction.json` and FastAPI unchanged, and describes flooded *objects*, not a continuous water surface. An executed synthetic example is in `experiments/accuracy-pipeline-20261005/extended-prediction-smoke/`. Unit tests run with `.venv-training/Scripts/python.exe -m pytest -q app/training tests/test_positive_sampler.py`; FastAPI contract tests use `.venv/Scripts/python.exe -m pytest -q app/ai-service/tests/test_groupnorm_checkpoint.py app/ai-service/tests/test_model_identity.py`.

## Data and leakage controls

The E4 split inventory is in `experiments/accuracy-pipeline-20261005/data_split_manifest.csv` and `split_audit.json`. Pseudo input manifests must use `split=unlabeled_train`; the generator rejects imagery at protected train/validation paths and the Louisiana-West reserved test directory. Two or more frozen teachers are required. Pseudo pixels outside both high-confidence positive and low-confidence negative consensus are 255 (ignored). Synthetic smoke data require an explicit flag and the saved output is marked non-training-eligible. GIS-derived vector masks carry CRS, metric road buffer, nodata, and hashes; they are weak object labels, not flood-water truth.

Train-only hard-negative mining reads E4 predictions and GT on the training split. Full-split metadata and matching tile IDs are mandatory before the optional 2–5× within-domain reweighting. The top fraction is configurable (`hard_negative_mining.top_fraction`, default 0.2). `training_sampling_report.json` and mining CSV/PNG provide evidence of what was sampled.

## Evaluation and release rule

All current metric comparisons use the same 18-image Germany development split and 0.5 threshold. `scripts/search_development_thresholds.py` records a fixed per-class grid but its optimized threshold is not deployed. `scripts/model_promotion.py` requires macro gain ≥0.005, no class regression >0.005, improved flooded-road IoU, nondecreasing flooded-road precision, and nonzero flooded-road recall/prediction. Even a passing decision is only `PROMOTE_DEVELOPMENT_CANDIDATE` with `production_ready=false`. Independent four-class held-out labels are required before production release. The current outcome is in `reports/ACCURACY_IMPROVEMENT_REPORT.md`.
